我第一次做諮商所預約管理工具時，很早就有一個想法：

**如果所有事情都可以直接在 LINE 裡，靠機器人一問一答完成就好了。**

不用另外做一套我還不太懂的操作介面，個案、心理師和櫃檯也不用重新學新的東西。大家本來就會用 LINE，那就讓系統直接在 LINE 裡工作。

所以實際的順序不是，我先把整套系統有哪些功能全部想清楚，再決定把它做進 LINE。比較接近的是：

**我先決定想用 LINE 對話來處理事情，接著才一邊了解現場工作，一邊把那些工作拆成一段一段的對話。**

這跟當時諮商所原本的工作方式也很有關係。

LINE OA 本來就是櫃檯跟個案、心理師之間很主要的聯絡管道。個案有事情可能從 LINE 詢問，櫃檯人工回覆；預約時間需要確認，也是在訊息中來回溝通；心理師有需要聯絡的事情，同樣很常透過 LINE 處理。

問題是，訊息雖然在 LINE 裡，後面的工作不一定也在 LINE 裡。櫃檯收到資訊之後，可能還要再把預約內容手動輸入其他工具或系統；確認完一件事情之後，也可能還要再人工通知下一個人。

當時也不是完全沒有預約系統可以用，只是我接觸到的情況裡，很多諮商所使用的，是原本為一般診所、醫美診所等場景設計的系統，只能挑其中一部分功能配合自己的工作方式使用；一些諮商所特有的工作，現有商業系統也不一定有提供。

所以我看到的並不是「大家什麼工具都沒有」。

而是很多工作本來就已經在不同地方進行，其中 LINE 又剛好是大家每天真的會碰到的地方。

那我自然就開始想：

**如果原本要靠櫃檯一個一個回覆的事情，可以直接交給 LINE 機器人呢？**

最開始的想法其實很簡單。使用者傳來一段訊息，機器人判斷他想做什麼，再回覆對應的內容。

例如使用者想預約，機器人就問下一個問題；對方回答之後，再繼續往下問。如果有不同選擇，就根據回答走到不同的對話。

我就是用這種方式，一邊理解原本的工作，一邊把它拆成：

「先問這個。」

「回答這個之後，再問下一個。」

「如果選 A，就往這裡走。」

「如果選 B，就換另一段。」

Day 3 提到，很多功能都是從觀察現場之後的「許願」慢慢長出來。而在當時，這些許願幾乎都很快進入同一個框架：

**這件事情要怎麼用 LINE 對話完成？**

如果原本需要櫃檯人工詢問幾個問題，那就讓機器人照順序問；如果原本需要人工確認資訊，那能不能讓使用者直接在對話裡選？如果一件事情完成之後要通知下一個人，那能不能讓系統自己接著處理？

所以功能並不是先在 LINE 外面完整長好，再被搬進對話裡。很多功能本身，就是我把人的工作拆成一次又一次對話來回之後慢慢形成的。

這種做法對當時的我還有一個很大的吸引力：

**大家幾乎不用另外學一套新的東西。**

個案本來就知道怎麼用 LINE，心理師也一樣。不用另外記一個網址，不用第一次打開一套完全陌生的畫面，再重新找「預約在哪裡」、「我要按哪裡」、「這個功能藏在哪裡」。

連帳號這件事情，我當時都想得很簡單。既然使用者本來就有自己的 LINE 帳號，那系統就可以知道現在是哪一個 LINE 使用者正在跟機器人互動。

我甚至覺得，這樣連另外做一套註冊和登入，好像都可以先省掉。

但除了使用者不用學新的東西之外，這個選擇其實也跟我自己的能力有很直接的關係。

那時候我開始接受前端訓練才幾個月，學過一些基礎的 JavaScript、TypeScript，也做過一點最基本的網頁切版。

但我的程度真的還非常淺。那時候我甚至還沒有學到 RWD，也就是同一個網頁要怎麼配合電腦、平板、手機不同大小的畫面調整。

至於一套完整的系統操作介面到底要怎麼規劃、怎麼拆成不同頁面、怎麼管理很多操作和資料，我更是離「知道自己在做什麼」還很遠。我甚至還不知道，後台管理這種操作介面可以有很多不同做法。

我只很模糊地知道：

**系統需要一個讓人操作的前端。**

但那個前端究竟可以長成什麼樣子，當時的我沒有很完整的概念。

這也讓 LINE 看起來更有吸引力。因為 LINE 已經幫我準備好一個使用者看得到、也知道怎麼操作的地方。

我不用先從一個空白頁面開始想：這裡要放什麼？按鈕在哪裡？不同功能怎麼切換？手機畫面要怎麼處理？之後功能變多了又要怎麼整理？

對一個幾個月前才剛經歷過「網站雖然做得出來，但是自己完全改不動」的人來說，這確實是一條看起來比較走得進去的路。

所以我那時候不只是覺得：

「LINE 很適合拿來當聯絡入口。」

我的想法其實更接近：

**如果 LINE 機器人已經可以跟使用者對話，那是不是乾脆所有操作都讓它用對話完成？**

個案、心理師都在 LINE 裡操作，櫃檯和經營者需要處理的事情，也盡量放進 LINE。

我不需要先弄懂一整套完整的前端，使用者也不用另外學一個新的系統。看起來兩邊的問題一起解決了。

現在回頭看，這也是我第一次很具體地碰到這個系列一直在談的「黏哪裡」。

當然，我當時根本沒有用這個詞。

我只是看到 LINE 原本就在工作流程裡，而且大家都已經會使用，就很自然地想沿著它繼續往下做。

只是接下來每多一個需求，我想到的仍然是同一件事：

**這件事情，要怎麼繼續拆成 LINE 裡的一段對話？**

那時候的願望很單純：

**如果所有事情都能交給 LINE 機器人完成，就好了。**
